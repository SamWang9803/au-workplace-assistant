# 设计：Fair Work RAG 助手的演示页

日期：2026-11-03 · 状态：2026-11-03 已实现
延伸自：[2026-11-02-fairwork-rag-design.md](2026-11-02-fairwork-rag-design.md)（第一阶段）
英文原版：`2026-11-03-demo-page-design.md`（两份内容有出入时以英文版为准）

## 1. 目标

一个网页，用于面试演示和手动测试：输入问题，看到回答和引用，同时看到检索到的
5 个分块及其相似度，这样混合检索和拒答规则可以演示出来，而不是口头描述。第一
阶段把「不做 Web 界面」列为非目标；这一行改为「只有一个最简演示页，生产还需要
真正的前端」。

## 2. 不做的事

多轮对话历史、流式输出、鉴权、多租户、手机端排版打磨、构建工具、外部资源
（字体、CDN）。

## 3. 做法

一个静态文件 `static/index.html`，CSS 和 JavaScript 内联，由 FastAPI 在 `GET /`
托管。页面用 `fetch` 调 `POST /ask` 并渲染返回的 JSON。不加任何依赖。

否决的方案：Streamlit（多一个进程和依赖，而且绕过了演示本该展示的 API）；
Gradio（聊天布局会让人以为系统有对话记忆，实际没有）。

## 4. API 改动

`POST /ask` 新增几个向后兼容的字段：

- 每条引用加 `rank`：它在 prompt 里的来源编号，页面给引用卡片编号时和模型看到的
  一致。
- `confidence`：`"high" | "medium" | "low" | null`（拒答时为 null）。
- `sources`：融合后的 top-5，按 prompt 里的顺序，每项为
  `{rank, document, page, snippet, similarity, cited}`。只被全文检索找到的分块
  `similarity` 为 null；分块编号在保留下来的引用里时 `cited` 为 true。

`GET /` 返回 `static/index.html`。`GET /health` 不变。

## 5. 页面

从上到下：

1. 页头：标题、一句说明，以及一个小的「API docs」链接，在新标签页打开 `/docs`。
2. 表单：文本框（最多 1000 字符）、Ask 按钮、5 个示例问题标签（通知期、圣诞节
   上班、养老金比例、工作 5 年的裁员补偿、482 签证）。点标签把问题填进文本框。
3. 状态条：绿色「Answered」或琥珀色「Refused」，后面是置信度、耗时（秒）、
   费用（美元）。
4. 回答正文（拒答时是那句固定的拒答语）。
5. 引用来源：每条引用一张卡片，编号和 prompt 里一致，显示文档名、页码和片段；
   片段截到 300 字符，点开展开。
6. 检索来源：默认折叠的 `<details>` 块，每个来源一行：名次、文档、页码、
   相似度（或「text only」）、是否被引用的标记。

状态：空闲（只有页头和表单）、请求中（按钮禁用，文字变成「Asking…」）、
有结果、出错。出错时各显示一句话：422 问题不合法、502 模型服务失败、503 数据库
不可用、网络错误。

界面文字用英文。文档名按语料里的样子显示（文件名去掉扩展名）。所有内容用
`textContent` 渲染，绝不用 `innerHTML`，因为片段是来自 PDF 的不可信文本。

## 6. 测试

`tests/test_api.py` 用 FastAPI 的 `TestClient`，把 `api.answer` 换成返回固定
`Answer` 的假函数，把 `db.log_query` 换成空操作：`GET /` 返回含标题的 HTML；
`POST /ask` 返回文档里列出的全部字段，其中 `sources` 的 `cited` 标记和引用一致；
空问题返回 422。不联网，不连库。

## 7. 文档

两份 README：运行步骤加「打开 http://127.0.0.1:8000/」，API 一节列出新字段，
非目标那一行按第 1 节修改，目录结构加 `static/`。第一阶段设计稿的非目标加一句
指向本文。

## 8. 验收

页面在浏览器里能回答 5 个示例问题；签证那题显示琥珀色的拒答；检索列表里的
「cited」标记和引用卡片一致；`pytest` 全绿。
